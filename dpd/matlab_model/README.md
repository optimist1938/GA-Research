# Трёхполосная DPD-модель с фазовой эквивариантностью: MATLAB-версия

Обычный MATLAB (R2016b и новее) или GNU Octave, toolbox не нужны.

## Состав

| Файл | Что это |
|---|---|
| `dpd_gated_tcn.m` | модель: `D = dpd_gated_tcn(X, model)` |
| `dpd_tcn16x4.mat` | компактная версия: 5 194 параметра, ≈5.1 тыс. умножений на отсчёт |
| `dpd_tcn64x5.mat` | точная версия: 86 314 параметров, ≈86 тыс. умножений на отсчёт |
| `dpd_selfcheck.m` | проверка, что MATLAB-код совпадает с исходной моделью на PyTorch |
| `run_example_geodata.m` | NMSE по полосам на GeoData_TB.mat (или на другой записи с теми же переменными) |

## Быстрый старт

```matlab
dpd_selfcheck('dpd_tcn16x4.mat')                                  % ожидается OK, ошибка ~1e-7
res = run_example_geodata('GeoData_TB.mat', 'dpd_tcn16x4.mat');   % NMSE на последних 20% записи
res = run_example_geodata('GeoData_TB.mat', 'dpd_tcn64x5.mat', true);  % + графики PSD
```

Прямой вызов:

```matlab
S = load('dpd_tcn16x4.mat');
X = [xA; xB; xC];                  % 3 x N, комплексные огибающие, единицы как в GeoData_TB
D = dpd_gated_tcn(X, S.model);     % 3 x N, поправка в единицах dA, dB, dC
e = dA - D(1, :);                  % остаток модели в полосе A
```

Длинные записи (800 тыс. отсчётов и больше) обрабатываются кусками по 65 536 отсчётов с перекрытием. Результат не зависит от размера куска; размер можно задать третьим аргументом.

## Как устроена модель

Для каждой полосы c выход строится так же, как в LUT-модели: сумма нескольких задержанных копий входа этой полосы с комплексными коэффициентами,

    D(c, k) = sum_{m=-3..3} x_c(k - m) * g_{c,m}(k).

Отличаются два момента.

1. **От чего зависит коэффициент g.** В LUT он зависит от амплитуд |x_A|, |x_B|, |x_C|. Здесь к ним добавлены приращения фазы каждой полосы между соседними отсчётами, x_b(k)·conj(x_b(k−1)) и x_b(k)·conj(x_b(k−2)). Ни амплитуды, ни приращения фазы не меняются при повороте фазы полосы целиком. Поэтому поворот фазы полосы b на постоянный угол поворачивает выход полосы b на тот же угол и не меняет две другие полосы. На данных GeoData_TB это свойство выполняется: члены, которые его нарушают, улучшения не дают (0.00 dB).
2. **Как вычисляется g.** Вместо таблицы коэффициенты выдаёт небольшая свёрточная сеть по времени. Это несколько слоёв коротких фильтров из 3 отсчётов с растущим шагом (1, 2, 4, 8, …) и нелинейностью GELU между ними, с остаточными связями. Все операции обычные: матричные умножения и `erf`.

## Результаты на GeoData_TB

Обучение на первых 80% записи, проверка на последних 20%. NMSE = 10·log10(Σ|d − D|² / Σ|x|²), как `nmse(xRef, e)` в SimpleNonLinearModel_ML; в скобках — нормировка на d.

| Модель | Параметры | Умножений на отсчёт | A | B | C |
|---|---|---|---|---|---|
| Ваша LUT-модель, структура из simpleModel (2 входа на полосу, Чебышёв 8-го порядка) | 7 290 | ≈11.3 тыс. | −24.1 | −22.3 | −23.0 |
| `dpd_tcn16x4` | 5 194 | ≈5.1 тыс. | −26.6 (−15.6) | −29.1 (−13.3) | −28.6 (−16.6) |

Строка LUT — наша реконструкция модели из simpleModel (`SimpleNonLinearModel_ML.m` с `PartModel` из `NonLinearProblemSimple.m`, полосы AB / BA / CA). Умножения посчитаны для формы с коэффициентами при базисе Чебышёва.

## Ограничения

- **Модель обучена на одной записи одного усилителя.** Проверка на другой записи того же PA в той же конфигурации (те же несущие, близкий уровень мощности, те же единицы) осмысленна. Для другого PA или другой конфигурации модель нужно переобучить: присылайте данные, переобучим, или передадим код обучения на Python.
- **Масштаб входа фиксирован.** Он сохранён в `model.scale` по мощности обучающей записи. Если уровень мощности на вашей записи другой, модель окажется вне диапазона, на котором училась.
- **Модель некаузальная.** Выход в момент k использует вход до k + 18 отсчётов вперёд у 16×4 (≈49 нс при 368.64 МГц) и до k + 34 у 64×5 (≈92 нс). Причинную версию можно обучить, если это требование.
- **Точность вычислений.** Веса хранятся в double, обучались в float32; расхождение с исходной моделью ~1e-7 относительно амплитуды d.
