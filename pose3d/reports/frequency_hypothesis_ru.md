# Почему GATr не учит многогранники: «частоты» по позе, объяснение с нуля

> **Обновление:** гипотеза подтверждена прямым экспериментом — GATr на облаках точек SYMSOL учит многогранники, только
> когда ему явно подают 49 гармоник положения точек в системе текущей позы (10 %: 1.47 → 7.58; бесконечные данные:
> 8.82 → 10.96). Подробности: `reports/fft_flow_points.md`.

Документ для того, кто входит в тему с нуля (человек или агент). Всё, что нужно, чтобы понять гипотезу,
проверить её и продолжить работу. Статус: **гипотеза, согласованная со всеми запусками, но ещё не доказанная
прямым измерением** (план проверки — раздел 7).

---

## 1. Контекст: что мы делаем

Проект GA-Research / `pose3d`: оценка 3D-позы объекта (поворот R ∈ SO(3)) по входу (картинка или облако точек)
через **flow matching на SO(3)**:

- берём случайную позу R₀ (равномерно по SO(3)) и учим поле скорости v(R, t | вход), которое за 20 шагов
  `R ← R·exp(dt·v)` переносит R₀ в правильную позу R₁;
- обучение: R_t — точка на кратчайшей дуге между R₀ и R₁, цель — скорость `log(R₀ᵀR₁)`, функция потерь MSE;
- если у объекта несколько правильных поз (симметрия), поток должен выучить **распределение** по ним;
  метрика на SYMSOL — log-likelihood по эквивалентным позам (равномерное распределение = −2.29).

Модели (все около 250 тыс. параметров «головы»):

| Модель | Как поза входит в сеть | Код |
|---|---|---|
| **GATr** (Geometric Algebra Transformer) | токены-мультивекторы R e₁, R e₂, R e₃ рядом с токенами входа; эквивариантный трансформер | `models/gatr_denoiser.py`, `models/clifford_flow.py` |
| **SO(3)-Fourier** (как image2sphere / Howell) | вход превращается в коэффициенты Фурье на SO(3) до l = 6; скорость читается из D(R)ᵀc | `models/so3fourier_head.py` |
| **GA-1** (сравнение через ротор) | шаблон-векторы p_j поворачиваются позой (R p_j R̃), сравниваются с точками входа через exp(κ cos) | `models/rotor_corr_head.py` |
| **DiT** (обычный трансформер) | 9 чисел матрицы R | `models/dit_flow.py` |

Датасеты: **SYMSOL I** (тетраэдр, куб, икосаэдр, конус, цилиндр; у каждой фигуры много эквивалентных поз),
**ModelNet10** (мебель, поза почти всегда одна). Оба — картинками и облаками точек
(`datasets/symsol.py`, `datasets/symsol_points.py`, `datasets/modelnet_points.py`).

**Наблюдение, которое надо объяснить:** GATr ни разу не выучил тетраэдр, куб и икосаэдр (log-likelihood ровно
−2.29, как у равномерного распределения) — ни по картинкам, ни по точкам, ни на 10 % данных, ни на бесконечных.
Конус и цилиндр выучивает. А на ModelNet из точек он лучший из всех моделей (медиана 2.7°).

## 2. Что такое «частота» — с нуля

### 2.1. На окружности (обычный ряд Фурье)

Любую функцию угла f(θ) можно разложить на волны:

```
f(θ) = a₀ + a₁ cos θ + b₁ sin θ + a₂ cos 2θ + b₂ sin 2θ + … 
```

**Частота k** — сколько раз волна повторяется за полный оборот:

- k = 0: константа;
- k = 1: один горб и одна яма — «смотрит в одну сторону»;
- k = 2: два горба напротив друг друга — «ось без направления»;
- k = 6: шесть горбов через 60°.

**Низкие частоты** — широкие, плавные узоры. **Высокие** — мелкие, с многими горбами.

### 2.2. На сфере (сферические гармоники)

Для функции направления f(x), |x| = 1, роль волн играют сферические гармоники Y_l, а роль k — число **l**.
У частоты l есть 2l + 1 независимых компонент.

**Самый практичный способ думать о l: это степень многочлена от координат (x, y, z).**

| l | Пример многочлена | Что описывает |
|---|---|---|
| 0 | 1 | константа |
| 1 | z | направление со знаком («куда смотрит вершина конуса») |
| 2 | z² − ⅓ | ось без знака («ось цилиндра, верх = низ») |
| 3 | x·y·z | узор тетраэдра |
| 4 | x⁴ + y⁴ + z⁴ − ⅗ | узор куба |
| 6 | (многочлен 6-й степени) | узор икосаэдра |

Функция «до частоты L» — это ровно многочлен степени ≤ L от x, y, z.

### 2.3. На SO(3) (функции позы)

Поза — матрица поворота R, 9 чисел. Функция позы f(R) тоже раскладывается по частотам l = 0, 1, 2, …
(базис — матрицы Вигнера D^l(R)). И снова: **частота l ≈ степень многочлена от элементов матрицы R.**
Например, R₃₃ (насколько ось z объекта смотрит вдоль z камеры) — частота 1; R₃₃² — частоты 0 и 2.

Поле скорости потока v(R, t) — тоже функция позы, и у него тоже есть «спектр» по l.

## 3. Симметрия убивает низкие частоты

### 3.1. Аналогия на окружности

Пусть функция повторяется каждые 60°: f(θ + 60°) = f(θ). Тогда в её ряду Фурье могут быть **только** частоты,
кратные 6: k = 0, 6, 12, … Частоты 1–5 обязаны быть нулём: волна cos θ не повторяется через 60°, и сумма её
шести сдвинутых копий равна нулю.

### 3.2. Для фигур

Правильное распределение поз симметричной фигуры (и правильное поле скорости к нему) не меняется при повороте
на любой элемент группы симметрии фигуры. Как и на окружности, это зануляет все частоты, которые этой
симметрии не удовлетворяют. Наименьшая ненулевая частота (не считая константы) — степень простейшего
инвариантного многочлена:

| Фигура | Симметрий (эквивалентных поз) | Простейший инвариант | **Минимальная частота** |
|---|---|---|---|
| конус | ∞ (вращение вокруг оси) | z (ось со знаком) | **1** |
| цилиндр | ∞ + переворот | z² (ось без знака) | **2** |
| тетраэдр | 12 | x·y·z | **3** |
| куб | 24 | x⁴ + y⁴ + z⁴ | **4** |
| икосаэдр | 60 | многочлен 6-й степени | **6** |
| несимметричный объект ModelNet | 1 | — | **1** (поле «повернись к одной позе») |
| ванна или стол ModelNet (перед = зад) | 2 | — | **2** |

Это было проверено и численно в ранних диагностиках: у точного (оракульного) поля скорости для SYMSOL
минимальная ненулевая частота — 3 / 4 / 6 / 1 / 2 (тетраэдр / куб / икосаэдр / конус / цилиндр).
См. `reports/symsol_p1_stall.md` и скрипты `~/rfeval/symsol/analysis_*.py`.

**Важное следствие:** у поля скорости многогранника **нет вообще ничего** в частотах 1 и 2. Модель, которая
умеет выражать только l ≤ 2, может в лучшем случае выдать на многограннике нулевую скорость.

## 4. Почему модели на старте умеют не все частоты

### 4.1. Общий принцип

Обучение — градиентный спуск, то есть цепочка малых поправок. Первые поправки могут добавить к полю скорости
только то, что выражается через **текущие признаки сети**. Если цель ортогональна всему, что сеть сейчас умеет
(у неё нет общих частот с признаками), то **градиент равен нулю**: сети «не за что зацепиться», и она стоит.
Аналогия: радиоприёмник, который ловит только длинные волны, не начнёт ловить УКВ, сколько ни крути ручку
громкости.

### 4.2. По моделям

- **SO(3)-Fourier.** Признаки — D^l(R)ᵀc для всех l ≤ 6, считывание линейно по ним. Частоты 1–6 доступны
  с первого шага, поэтому учатся все фигуры.
- **GATr-денойзер.** Поза входит векторами R e_a — это степень 1 по R. Скалярное произведение в внимании
  ⟨q(R), k(вход)⟩ тоже степени 1. На первом порядке (малые поправки от инициализации) поле получает частоты
  **l ≤ 2**. Более высокие степени GATr может построить только перемножением через несколько слоёв:
  геометрическое произведение, гейтинг. Но на старте каждый множитель мал, и произведение k малых чисел мало
  в k-й степени. Градиент к l = 3, 4, 6 подавлен экспоненциально.
  → Конус (l = 1) и цилиндр (l = 2) учатся сразу; у многогранников градиента нет, сеть оставляет их на нулевой
  скорости и «гасит» их активации. Падение активаций в 15 раз и градиентов в 30–100 раз, найденное раньше
  (`reports/symsol_p1_stall.md`), — **следствие**, а не причина.
- **GA-1.** Признаки exp(κ⟨x_i, R p_j⟩) содержат все частоты, но с весом примерно e^(−l²/2κ). При κ = 10:
  l = 3 → 0.55, l = 4 → 0.37, l = 6 → **0.12**. Предсказание: тетраэдр и куб учатся, икосаэдр нет — так и вышло.
- **DiT / MLPFlow.** R — 9 чисел (степень 1) через нелинейные MLP. Высокие степени возникают слабо.
  Предсказание: «лестница» — частично тетраэдр, хуже куб, икосаэдр никогда. На ResNet-101 так и было:
  4.65 / 2.19 / −2.29.

### 4.3. Второе условие (почему DiT + Вигнер тоже не выучил)

Одних высоких частот по позе мало. Нужна ещё **связь**: ориентация фигуры во входе должна поворачивать узор,
с которым сравнивается поза. В SO(3)-Fourier и GA-1 это встроено эквивариантно. DiT, получив D^l(R) до l = 6
на вход, многогранники не выучил: ему эту связь пришлось бы выучить из данных. Учатся только модели, где
выполнены **оба** условия: (1) высокие l по позе на старте и (2) эквивариантная связь вход ↔ поза.

### 5.4. Как результаты согласуются с гипотезой

- **GATr:** выучено всё с минимальной частотой ≤ 2 (конус, цилиндр, ModelNet, включая симметричные
  классы порядка 2), не выучено ничего с частотой ≥ 3. Это не зависит от входа: картинка, точки, 10 % или
  бесконечные данные.
- **GA-1:** граница проходит между l = 4 (куб выучен) и l = 6 (икосаэдр нет), как и предсказывают веса ядра.
- **DiT:** «лестница» по l.
- **SO(3)-Fourier:** все частоты есть с начала — учит всё. На ModelNet он хуже GATr по другой причине:
  у его энкодера облака точки не взаимодействуют между собой (см. 6).

## 6. Что доказано, а что нет

**Доказано (измерено):**
- минимальные частоты точных полей скорости (раздел 3.2);
- на остановившемся P1 скорость на многогранниках почти ноль, активации и градиенты подавлены
  (`reports/symsol_p1_stall.md`);
- таблица результатов выше.

**Не доказано (гипотеза):**
- что на инициализации GATr у градиента нет компонент с l ≥ 3. Это объясняет все наблюдения, но напрямую
  не измерено;
- что на ModelNet SO(3)-Fourier проигрывает из-за энкодера облака, а не из-за считывания.

**Альтернативы, которые стоит держать в голове:**
- проблема оптимизации (learning rate, нормировки) — против: многогранники не учатся ни при каких рецептах;
- проблема входа — против: точки ничего не изменили;
- слишком маленькая модель GATr — не проверено (все модели около 250 тыс. параметров).

## 7. Как проверить

### 7.1. Спектральный тест градиента на старте (минуты на CPU, обучать не нужно)

Для каждой модели на случайной инициализации:
1. Взять вход фигуры (например, облако куба из `SymsolPoints`) и много поз R_t, t.
2. Посчитать оракульную цель — точное поле E[ξ | R_t] (закрытая формула есть в `~/rfeval/symsol/diagnose.py`,
   функция `oracle_velocity`).
3. Посчитать градиент потери по параметрам и, главное, **первую поправку к полю скорости**: δv = J Jᵀ ∇L, где
   J — якобиан скорости по параметрам. Это то, как поле изменится после малого шага.
4. Разложить δv по частотам l (проекцией на D^l(R) по сетке поз) и сравнить с целью.

Ожидание по гипотезе:
- у GATr-денойзера для куба, тетраэдра и икосаэдра совпадение δv с целью около нуля, для конуса и цилиндра —
  заметное;
- у SO(3)-Fourier заметное у всех;
- у GA-1 падает к l = 6.

### 7.2. Гибрид

GATr-энкодер облака (сильный вход) + считывание SO(3)-Fourier (все частоты). Ожидание: около 2.7° на ModelNet
и выученные многогранники на SYMSOL из точек.

### 7.3. Дать GATr высокие частоты явно

Подать в токен позы GATr инвариантные признаки высоких частот, например оценки сравнения GA-1 или
коэффициенты D(R)ᵀc из SO(3)-Fourier как скалярные каналы. Если многогранники пойдут — гипотеза подтверждена
напрямую.

## 9. Словарь

- **SO(3)** — множество всех поворотов в 3D.
- **Поза** — поворот R объекта относительно его канонической системы координат.
- **Частота l** — «степень мелкости» узора; для функций на сфере или SO(3) — степень многочлена от координат.
- **Эквивалентные позы** — повороты, при которых симметричная фигура выглядит так же.
- **Эквивариантность** — повернул вход, и выход повернулся так же.
- **Log-likelihood** — log плотности, которую модель даёт правильной позе; −2.29 = «не знает ничего».
- **Оракульное поле** — точная оптимальная скорость, посчитанная по формуле из истинных эквивалентных поз.
