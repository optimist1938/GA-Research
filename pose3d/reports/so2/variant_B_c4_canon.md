# Вариант B: C4-канонизация вокруг обученной модели (`pose3d.models.c4_canon`)

Статус: черновик v1. Ждёт ревью и запуска.

## 1. Идея

Вместо того чтобы делать эквивариантной саму сеть, приводим картинку к канонической ориентации и вызываем **неизменённую** обученную модель f₀ (рецепт 8.95°):

```
c(x) = argmax_k  s( rot90(x, −k) )            k ∈ {0,1,2,3},  s — оценка «вертикальности» одного вида
f(x) = G^{c(x)} · f₀( rot90(x, −c(x)) )       G = R_z(−90°): смена метки при повороте картинки на 90° против часовой стрелки
```

s(view) — логистическая регрессия на пулированных признаках ResNet-101 самой f₀ (2049 чисел). Она обучается отличать вертикальный вид от трёх повёрнутых на **train**-картинках; это prior канонизации к тождеству из Mondal et al. 2023. Сама f₀ заморожена, переобучать её не нужно.

## 2. Строгие утверждения (Lean, `pose3d/proofs/so2`)

| утверждение | теорема |
|---|---|
| если c — строгий argmax по орбите для x, то для g·x строгий argmax равен g·c(x), при **любом** скорере s | `Symmetry.orbit_argmax_equivariant` |
| эквивариантный канонизатор делает эквивариантной **любую** f₀ | `Symmetry.canonicalize_equivariant` |
| на картинках с c(x) = 0 обёртка совпадает с f₀ | `Symmetry.canonicalize_of_canonical` |
| ошибка на повёрнутом тесте поэлементно равна ошибке на исходном | `Symmetry.equivariant_error_invariant` |
| физика: поворот картинки — это R ↦ R_z R на центрированных warp-кропах | `Camera.project_roll`, `Camera.roll_posed` |

Численная проверка (`tests/test_c4_lift.py::test_c4_canonicalized_model_is_exactly_equivariant_and_keeps_upright_predictions`):
- c(rot x) = c(x) + 1;
- f(rot x) = G·f(x) поэлементно при одинаковом шуме сэмплинга;
- на картинках с c = 0 обёртка совпадает с f₀.

## 3. Чего ожидать

- **Повёрнутые тесты (90°, 180°, 270°).** Ошибка точно равна ошибке на исходном тесте (теорема). У baseline это 96° и 176°.
- **Обычный тест.** Модель равна f₀ на всех картинках, где канонизатор выбирает k = 0. На картинке, где он ошибся, предсказание повёрнуто на 90° или 180°: ошибка ≥ 80°. Если доля ошибок канонизатора на вертикальном тесте равна p, медиана почти не сдвигается при p ≪ 50%, а acc@15 и acc@30 падают примерно на p. Значит, вариант B выгоден, только если p ≲ 0.5–1%. Оценку p даёт проба «верха» (раздел 4).
- **Цена.** Четыре прохода бэкбона в инференсе (если признаки для скорера и для f₀ не шарить: проход k = c(x) можно переиспользовать, это ×4 вместо ×5) и ноль GPU-часов на обучение.

## 5. Риски

- Канонизатор выбирает **дискретный** поворот, поэтому остаточный roll в пределах ±45° остаётся задачей f₀. Это нормально: f₀ устойчива до ±20°.
- **Неоднозначные картинки.** Вид сверху, симметричные объекты (bottle, diningtable) — там s может ошибаться. Ошибка стоит 90–180°, а не долей градуса.
- Вариант B не улучшает **саму** модель на вертикальном тесте. Это обёртка-гарантия, а не новая архитектура признаков, и сравнивать её надо с вариантом A по цене и надёжности.

## 6. Протокол запуска

Один короткий кернел без обучения f₀:

```
python -m pose3d.eval_rotations --checkpoint <8.95 ckpt> --path_to_datasets <pascal3d> --steps 20 --eval_samples 32
python -m pose3d.eval_rotations --checkpoint <8.95 ckpt> --path_to_datasets <pascal3d> --steps 20 --eval_samples 32 --canonicalize
```

Первая команда даёт baseline на повёрнутых тестах, вторая — вариант B.

Критерий успеха:
- на обычном тесте class-mean ≤ baseline + 0.1°;
- точность канонизатора на вертикальном тесте ≥ 99%;
- на повёрнутых тестах ошибка совпадает с обычной.
