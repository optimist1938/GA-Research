# Вариант B: C4-канонизация вокруг обученной модели (`pose3d.models.c4_canon`)

Статус: **v2, после ревью. Отклонён до GPU-запуска:** CPU-пробы показали, что он не проходит собственный критерий.

## 1. Идея

Сеть не меняется. Картинка приводится к канонической ориентации, и на ней вызывается **неизменённая** обученная модель f₀ (рецепт 8.95°):

```
c(x) = argmax_k  s( rot90(x, −k) )            k ∈ {0,1,2,3},  s — оценка «вертикальности» одного вида
f(x) = G^{c(x)} · f₀( rot90(x, −c(x)) )       G = R_z(−90°)
```

s — логистическая регрессия на пулированных признаках ResNet-101 самой f₀, обученная на **train**-картинках: вертикальный вид против трёх повёрнутых. Это prior канонизации к тождеству из Mondal et al. 2023.

**Чем это является и чем нет** (ревью, пункт 5). Это test-time C4-канонизация в духе Kaba et al. 2023, а не архитектура, уважающая SO(2):
- признаки и головы не меняются;
- вся неэквивариантность перенесена в обученный «детектор верха», который и есть upright-prior;
- обёртка точно эквивариантна только к C4 и разрывна: около ничьих маленькое возмущение переворачивает ответ на 90°;
- на вертикальном Pascal3D она может только сравняться с f₀ или проиграть.

## 2. Строгие утверждения (Lean, `pose3d/proofs/so2`)

| утверждение | теорема |
|---|---|
| если c — строгий argmax по орбите для x, то для g·x строгий argmax равен g·c(x), при любом скорере | `Symmetry.orbit_argmax_equivariant` |
| в точке, где канонизатор эквивариантен, канонизированная f эквивариантна (поточечно, как это и даёт argmax) | `Symmetry.canonicalize_equivariant_at` |
| глобальная версия (при эквивариантном канонизаторе всюду) | `Symmetry.canonicalize_equivariant` |
| где c(x) = 0, обёртка совпадает с f₀ | `Symmetry.canonicalize_of_canonical` |

Численная проверка: `test_c4_canonicalized_model_is_exactly_equivariant_and_keeps_upright_predictions` и `test_turn_matrix_is_r_z_minus_90`. Знак G отдельно сверен с конвенцией warp, ревьюер подтвердил его независимо.

## 3. Пробы (CPU) и вывод

Точность канонизатора на вертикальных картинках, 1309 val-картинок × 4 поворота. Признаки ResNet-101 из CGENN-baseline:

| канонизатор | протокол | точность |
|---|---|---|
| бинарный скорер (`probe_up.py`) | 981 train / 328 test | 93.0% (95% CI 89.7–95.4%) |
| бинарный, стандартизация признаков (`probe_up2.py`) | 5-fold CV | 93.1% |
| 4-классовый RotNet, логрег, совместное правдоподобие по 4 видам | 5-fold CV | 92.2% |
| 4-классовый RotNet, MLP (512) | 5-fold CV | 93.2% |

Все модели упираются в один потолок ~93%. Около 7% кропов неоднозначны на уровне самих признаков: вид сверху, симметричные объекты, объект на однородном фоне. Мощность классификатора тут не помогает.

Критерий из v1 — p ≤ 0.5–1%, то есть точность ≥ 99%. Фактически p ≈ 7%, в 7–14 раз выше порога.

Ожидаемый эффект на обычном тесте (уточнён по ревью, пункт 4). Если сбои независимы от ошибки f₀, новая медиана равна F⁻¹(0.5/(1−p)). Наклон кривой ошибок около медианы ≈ 30° на единицу квантиля (7.85° на квантиле 0.5, 15° на 0.74). Отсюда:
- при p = 1% медиана сдвинется примерно на +0.15°;
- при p = 7% — примерно на +1.1° pooled;
- по классам больше, потому что сбои группируются в отдельных классах.

**Вывод: GPU-запуск не нужен.** Его результат предсказуем: регрессия на обычном тесте около +1° class-mean и тавтологическое равенство на поворотах, кратных 90°. При канонизации повёрнутые на 90°, 180° и 270° входы дают тот же канонический вход, что и 0°.

## 4. Что из варианта B пригодилось

- **`RollPrior`.** Та же информация о верхе, но в виде явного мягкого приора на сэмплы, а не жёсткого выбора поворота. Повёрнутые моды получают вес ~1e-10. Используется в варианте A, раздел 5.
- **Оценка `eval_rotations`:** произвольные углы, связанный шум, дамп по каждому примеру, точность канонизатора по классам.
- Честная точка сравнения для «устойчивости» варианта A — f₀ с C4-аугментацией при обучении, а не обёртка.
