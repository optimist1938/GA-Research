# pose3d

**Best score**: Clifford Flow with a GATr vector field, ResNet-101, trained on Image2Sphere's data (warp + synthetic renders) with EMA weights: **8.95°** mean of per-class median errors, **7.85°** median over all test images, on Pascal3D+ (`clifford_flow_gatr_warp_synth_ema_b64`, Kaggle kernel `syfry5suvzovvakmuj/clifford-gatr-ema-b64-rtx`) — now the default recipe in `pose3d/config.py`.

| Status | Idea | Description |
|---|---|---|
| Tried, worse | Endpoint (x1) parametrisation of Clifford Flow | `--flow_param x1 [--x1_loss tangent\|geodesic]` (branch `flow-x1-prediction`): the vector field predicts the remaining displacement log(rt~ r1), bounded by pi, instead of the constant velocity; the sampler divides by (1-t) and its last Euler step lands on the predicted endpoint (the x0-prediction of diffusion models). Two runs (n=1 each, 32-sample medoid), both slightly worse than their baselines: on the best data recipe (warp + synth pack + EMA + batch 64, RTX) `clifford_flow_x1_warp_synth_ema_b64` gives **8.52 deg median / 10.02 deg class-mean** vs 7.88 / 9.82 (`clifford_flow_cgenn_warp_synth_ema_b64`); on the main recipe (T4 x2) `clifford_flow_x1_t4` gives **9.78 deg median** vs 9.63 (`mnpsfhmd`). The tangent loss reweights the reference loss by (1-t)^2, so parametrisation and reweighting are confounded; `--x1_loss geodesic`, or an x1 output trained with the unweighted velocity loss, would separate them. |
| Idea | GATr with a condition mask and a KV cache | The GATr vector field runs 4 blocks of full self-attention over rotor + time + 64 condition tokens on every Euler step, so nothing per image can be precomputed. Mask the attention so condition tokens attend only to condition tokens (rotor and time attend to everything) and drop `t` from the condition tokens' scalar channel: their states then stay fixed across steps and samples, the K/V of every block are computed once per image, and a step costs two query tokens against cached keys (~30x less work). A different model (needs retraining and xformers masks), not an eval-time optimisation; compare with the exact Clifford fast-path in `docs/superpowers/specs/2026-10-05-fast-clifford-flow-predict-design.md`. |
